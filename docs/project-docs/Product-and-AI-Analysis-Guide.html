Turn an AI review into a study you can revisit.

TensuGo is a desktop workspace for reviewing Go games with a local KataGo engine. It keeps the board, game tree, candidate moves, variations, and your study notes together so that an engine result can become a useful explanation and a future training target.

A review workflow, not just an engine window

1. Open the real game

Import an SGF, GIB, or TensuGo study file and move through its game tree. Main line, variations, annotations, and meaningful branches remain attached to the position that produced them.

2. Analyze the position before the played move

Automatic analysis asks the engine about the position immediately before each actual move. Candidate ranks and losses therefore describe the choice available to the player, rather than a position reconstructed after the move.

3. Inspect alternatives and preserve the lesson

Use candidate moves, visits, win rate, score, and principal variation to examine a turning point. Keep the variations that explain the idea. TensuGo is designed to turn selected moments into structured study material, not leave a list of raw engine lines.

How to read an AI analysis

Candidate move
A move considered by the configured KataGo engine at the current position. The report uses a limited recorded window of leading candidates.
Visits
Search effort allocated by the engine. More visits generally mean stronger engine support in that run; visits are not a probability and depend on the model, hardware, and analysis budget.
Win rate / score
Engine evaluation fields for the current configuration. They compare alternatives in the same analysis; they are not a universal measurement of player strength.
Principal variation
An illustrative continuation to investigate, not a claim that every move is forced.

If the board does not show candidate bubbles or other AI information, first check that the selected node has completed analysis and that the relevant display option is enabled. Candidate information belongs to a specific position.

Tianshu report: match degree and match rate

The Tianshu report summarizes how often played moves were supported by leading engine candidates. It helps find positions worth reviewing; it is not a label for whether a player is “good” or “bad.”

Match degree (吻合度)

A continuous measure of engine support. For each successfully analyzed move, TensuGo divides the played move's visits by the visits of the strongest recorded candidate. If the played move is not in the recorded candidate window, its score is 0. The report averages those scores and displays a percentage.

move match degree = played candidate visits / best candidate visits
average match degree = average across all analyzed moves

Match rate (吻合率)

A pass rate, not an average score. A move counts as a match only when it is in the top 3 recorded candidates and its visits are at least 20% of the top candidate's visits. The report divides matching moves by all successfully analyzed moves.

match = rank is 1–3 AND played visits / best visits ≥ 20%
match rate = matching moves / analyzed moves

Related terms

Top-move hit rate counts moves ranked first. Candidate hit rate counts moves found anywhere in the recorded candidate window. A fourth- or fifth-ranked move can contribute to match degree and candidate hit rate, but cannot pass the top-3 match-rate rule.

Worked example

Suppose the leading candidate has 1,000 visits. The same position is interpreted as follows.

Rank 1, 1,000 visits
Match degree: 100%. Counts toward match rate.
Rank 2, 600 visits
Match degree: 60%. Counts toward match rate.
Rank 3, 150 visits
Match degree: 15%. Does not count because it is below the 20% visit threshold.
Rank 5, 300 visits
Match degree: 30%. Does not count because it is outside the top 3.
Not recorded
Match degree: 0%. Does not count.

What the numbers do—and do not—say

  • They compare a game with one engine, model, search budget, and candidate window.
  • They help locate review points and track a repeatable study process.
  • They do not directly measure rank, creativity, fighting spirit, or the objective value of every move.
  • A move outside the recorded candidate window receives 0 for match degree; that means the run did not record it as a leading candidate, not that it is proven impossible or worthless.
  • Changing the engine configuration or analysis budget can change candidate order and visits. Compare reports only under reasonably comparable conditions.

Local-first by design

TensuGo is built around local game files and a local KataGo configuration. Your review work stays on your computer by default; a cloud engine is not required to analyze a position. Account services, when used, are separate from the local analysis workflow and have their own prompts and policies.

macOS users: macOS manages memory with compression and swap — memory an app frees is not marked free immediately, but stays in compressed/cached pages and is only reclaimed under memory pressure. This is a native macOS behavior, not an oversight in TensuGo: TensuGo does release the memory normally, macOS just does not return it to the system right away. Because TensuGo's AI analysis allocates a large block at once, this "not returned right away" effect is easy to notice, and Activity Monitor can keep showing high usage even after the app frees it. Exiting the process reclaims the memory fully and usage drops at once, so quit TensuGo (Cmd+Q) when you are done and do not leave a long-running analysis unattended.
